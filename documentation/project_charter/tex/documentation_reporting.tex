\subsection{Major Documentation Deliverables}
Throughout the life cycle of the PSIEM project, the team will generate and maintain documen-
tation artifacts that track requirements, design, progress, and results. All editable sources live in a
private GitHub repository (version control, issues, and project board) and a shared Google Drive
(PDF exports and presentation copies). Unless stated otherwise, artifacts are updated each sprint
and finalized per Senior Design deadlines.

\subsubsection{Project Charter}
Created in Sprint 1 as the guiding contract between the team, stakeholders, and faculty sponsor
(Prof. Gieser). Minor revisions occur only when scope or direction changes are approved by the
team and sponsor. Final Charter is submitted at the end of Senior Design I.

\subsubsection{System Requirements Specification}
This will outline all the functional/non-functional requirements for the PSIEM system. The document will be updated each time new requirements are classified or old ones are modified. The final version should be submitted through Senior Design.

\subsubsection{Architectural Design Specification}
This will describe the architecture of PSIEM, we will also include the choices of frameworks, cloud platform, and communication, and make sure they are up to date. The initial version should be completed by Sprint 3, and updates will occur until all the design requirements are agreed upon. The final Architectural Design Specification will be delivered near the end of Senior Design 1.

\subsubsection{Detailed Design Specification}
This specification will go into more detail for the architecture, into module-level details, that will include algorithms we might use or specific interface designs that might be used. The initial draft will be prepared by Sprint 4 after the architectural design. The final Detailed Design should be given by Senior Design 2, when actual implementation begins to start.

\subsection{Recurring Sprint Items}
\subsubsection{Product Backlog}
Items are derived from the SRS and PSIEM Breakdown. We add, refine, and prioritize work
in GitHub Projects (columns: Todo, In Progress, Review, Done). Design diagrams live in
Lucidchart and are linked from issues. Prioritization is by group consensus during Sprint Planning.

\subsubsection{Sprint Planning}
Held on Discord at least two days before each sprint review. Scope, acceptance criteria, owners,
and estimates are recorded in GitHub issues and meeting notes (Google Docs). We anticipate four
sprints in Senior Design I and five in Senior Design II (subject to the course calendar).

\subsubsection{Sprint Goal}
Drafted by the Scrum Master and finalized by team consensus. Goals emphasize demonstrable
increments (e.g., End-to-end log path: Beats --> Fluentd --> OpenSearch --> Dashboard).

\subsubsection{Sprint Backlog}
Selected from the highest-priority product backlog items during planning. Tracked in GitHub
Projects with assignees and due dates. The board is the single source of truth for in-sprint work.

\subsubsection{Task Breakdown}
Tasks are assigned by expertise and availability; pairing is encouraged. Each member logs ef-
fort (hours) in a shared spreadsheet per sprint. Issue comments capture day-to-day progress and
blockers.

\subsubsection{Sprint Burn Down Charts}
The Scrum Master generates a burn down at sprint end using GitHub issue counts and the effort
log. Charts (PNG/PDF) are stored with sprint notes and appended to the review deck.

\subsubsection{Sprint Retrospective}
Held immediately after the review. We capture: Start/Stop/Continue, top 3 improvements, and
one concrete action item per member. Group notes and individual reflections are due within 24
hours of the retro.

\subsubsection{Individual Status Reports}
Submitted by each member at sprint end. Contents: tasks completed, hours, obstacles, risks, and
goals for the next sprint. Stored in the repo under /reports/<sprint>/ and on Drive.

\subsubsection{Engineering Notebooks}
Each member updates their notebook weekly (minimum one page). Peer witness sign-off is required
bi-weekly. Snapshot PDFs are archived per sprint.

\subsection{Closeout Materials}


\subsubsection{System Prototype}
A working SIEM prototype demonstrating ingestion (Beats), parse/normalize (Fluentd or Logstash),
indexing (OpenSearch/Elasticsearch), dashboards (React), auth (Keycloak), and basic IDS (Suri-
cata/Zeek). Demonstrated during Senior Design II final presentations with a prepared dataset. If
time permits, a limited PAT will be conducted with a faculty observer.

\subsubsection{Project Poster}
A (36 by 48) poster summarizing objectives, architecture, results, and lessons learned. Delivered by
the department poster deadline; archived as PDF.

\subsubsection{Web Page}
A simple, public-facing page on a university-approved domain with overview, team bios, architecture
diagram, and links to artifacts. Published at project closeout.

\subsubsection{Demo Video}
A 5 to 7 minute narrated demo covering scenario, pipeline, alerting, and UI. B-roll (30 to 60s) included
for future cuts. Delivered with captions and archived on Drive.

\subsubsection{Source Code}
Maintained in a private GitHub repository using trunk-based development and PR reviews. At
closeout, the repository is exported (ZIP) with tags and handed off with installation instructions.
License: MIT (LICENSE file at repo root).

\subsubsection{Source Code Documentation}
Docstrings (PyDoc/Javadoc-style) and docs/ site (generated HTML). Final docs are delivered as
browsable HTML and PDF.

\subsubsection{Hardware Schematics}
Not applicable (software-only project).

\subsubsection{CAD files}
Not applicable (software-only project).

\subsubsection{Installation Scripts}
Containerized deployment using Docker Compose for development and demo; cloud notes for Azure
(AKS/ACI) if used. Scripts and env templates provided under /deploy/.

\subsubsection{User Manual}
A concise digital user guide (PDF) detailing setup, login, data ingestion, dashboards, and basic
troubleshooting. Linked from the web page and included in the final handoff.
